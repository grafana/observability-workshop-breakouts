# Lab 2 - It's always the database

A new complaint about the `ecommerce` store: product pages hang for several seconds before the recommendations appear. It's slow rather than broken, and it started recently. This time the trail doesn't stop at the browser - it leads through a trace and into the database.

In this lab you'll use [Database Observability](https://grafana.com/docs/grafana-cloud/monitor-applications/database-observability/) (GA since April 2026; MySQL and PostgreSQL, self-managed or managed - RDS, Aurora, Cloud SQL, Azure; collected by Grafana Alloy with no agent on the database host). You'll work through the **Queries Overview**, per-query metrics, the **Explain Plan**, **Table Schema Details**, and the Grafana Assistant's query optimization.

## Instructions

Use the Grafana Cloud stack from the slides. This lab uses the `ecommerce` app and its **orders database**.

:::info The scenario running

A k6 load test drives steady browse and checkout traffic while the **`recommendationsFromOrderAnalysis`** feature flag switches the recommendation service to build its "you might also like" results with an inefficient query against the orders database. Expect product pages to hang for several seconds while recommendations load, with the delay tracing down to a single expensive SQL query - not a broken service.

It runs automatically **every day during the `{LAB2_WINDOW}` window** (default 09:00-10:00 UTC - your facilitator will share today's exact times). Set your Grafana **time range** to cover that window - the accumulated query history is what fills the Queries Overview, samples, and explain plans.

:::

You have around 20 minutes to work through the questions.

:::tip

Try each question on your own first. The **Show answer** block under each question reveals the walkthrough and screenshots.

:::
