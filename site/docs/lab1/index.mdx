# Lab 1 - Users say slow, dashboards say fine

Support tickets are coming in about the `ecommerce` store: the site feels sluggish, and product images take forever to appear. Backend dashboards look fine - CPU is calm, error rates are flat, every service reports healthy.

In this lab you'll use [Frontend Observability](https://grafana.com/docs/grafana-cloud/monitor-applications/frontend-observability/) - Grafana's real user monitoring product, powered by the [Faro Web SDK](https://grafana.com/docs/grafana-cloud/monitor-applications/frontend-observability/instrument/faro/) - to find a problem that only exists in the browser. You'll work through Core Web Vitals, per-page performance, errors, user sessions, and the trace correlation that connects the frontend to the backend.

## Instructions

Go to the URL in the slides for your Grafana Cloud stack. This lab uses the `ecommerce` app.

:::info The scenario running

A k6 load test drives steady user traffic against the store while the **`imageSlowLoad`** feature flag injects the fault: it adds a 1.5-3 second delay to the banner and product images. Expect Largest Contentful Paint (LCP) to be in the "poor" range on image-heavy pages, while page loads still succeed and errors stay flat - a pure performance regression with no backend errors.

It runs automatically **every day during the `{LAB1_WINDOW}` window** (default 06:00-08:00 UTC - your facilitator will share today's exact times). Set your Grafana **time range** to cover that window; starting slightly before it lets you see the healthy baseline and when the regression begins.

:::

You have around 20 minutes to work through the questions.

:::tip

Try each question on your own first. The **Show answer** block under each question reveals the walkthrough and screenshots.

:::
